# Milestone 10 Report — Accounts and Progression Foundation

## Gate status

**Credential-blocked partial gate.** The repository now has a backend-neutral progression
contract, deterministic fake backend, configuration validation and security-oriented tests.
Real PlayFab identity, inventory/economy, statistics/leaderboards and remote configuration
remain blocked because no title ID, SDK/package, account or secret configuration is present.

## Implemented

- `IProgressionBackend` defines guest login, identity linking, display names, profile,
  idempotent match rewards, cosmetic ownership, trusted leaderboard writes and remote config.
- `FakeProgressionBackend` provides deterministic Android/Web guest identities, conflict-safe
  linking, display-name validation, XP/level and soft-currency progression, cosmetic inventory,
  server-validated idempotent rewards and trusted leaderboard sorting.
- `PlayFabBackendAdapter` is an explicit unavailable seam returning `CredentialsRequired`;
  it contains no SDK reference, title ID, secret or client-side account-creation path.
- `BackendConfiguration.LocalProof` keeps local tests unconfigured and prevents secrets from
  entering Android, WebAssembly or Git.

## Research decision

Current Microsoft PlayFab documentation indicates: new titles disable client-side anonymous
player creation by default (server-side creation is required); Economy v2 is generally
available and its inventory operations support idempotency; leaderboards are maintained from
trusted statistics rather than direct client score mutation. These claims and links are in
`Docs/RESEARCH_LOG.md`. The future real adapter must therefore use a server-controlled guest
creation/link flow and Economy v2-style idempotency, not a client secret or direct score write.
