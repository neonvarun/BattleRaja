# Milestone 3 Report — First Complete Fighter — Bijli

## Gate status

**Provisional technical pass.** Bijli is spawnable in MovementLab and her electric
bolt and directional dash work end to end. Pure state, command and collision-boundary
tests pass. Bolt/dash balance, physical touch ergonomics, HUD readability, visual feel
and formal performance profiling remain open human-review debt.

## Implemented

- Stable typed `ContentId` values for fighter, attack and ability content.
- Immutable `FighterDefinition` and `DashAbilityDefinition` data with a composed
  `FighterDefinitionAsset` for Bijli.
- Per-fighter `FighterRuntimeState` with startup, active, recovery and cooldown states;
  no mutable runtime state is stored in ScriptableObject assets.
- Shared `AbilityCommand`/`IAbilityCommandSink` boundary suitable for later bot and
  network command producers.
- Bijli electric bolt uses the existing central projectile, damage and pooling path,
  with data-driven M3 damage, cadence, speed, range, lifetime and radius.
- Collision-safe directional dash with aim → movement → facing → up fallback,
  CharacterController application, explicit play-space bounds and physics truncation.
- Non-authoritative TrailRenderer placeholder, Android ability button, desktop Space
  binding and a health/bolt/dash cooldown HUD.
- Movement is locked only during dash action phases; attack and movement regressions
  remain covered by the full suites.
