# Milestone 4 Report — Bot AI Laboratory

## Gate status

**Provisional technical pass.** Seven Bijli bots spawn in the shared MovementLab,
perceive only line-of-sight actors, produce common movement/attack/ability commands,
respect existing cooldown/collision rules and recover from blocked movement. The
seven-bot timing evidence is a headless-editor baseline; device-tier performance,
bot fairness/readability and manual debug-overlay review remain open.

## Implemented

- Pure `BotDifficultyProfile`, `BotPerceptionSnapshot`, `BotDecision`, seeded random,
  utility target scoring and `BotDecisionEngine` in the Domain assembly.
- Explicit line-of-sight eligibility and bounded cached observation snapshots.
- Explore, engage, reposition, retreat and recover decisions with configured reaction
  delay, imperfect aim noise and health retreat threshold.
- `BotNavigationRecovery` timeout/clear behavior for common blocked-progress deadlocks.
- `BotBrain` bridge that continuously submits existing movement commands and sends
  attack/dash commands through the M2/M3 ports; existing combat cooldowns and collision
  filtering remain authoritative.
- Optional `BotDebugOverlay` exposing state, target, utility, threat count and recovery.
- Seven uniquely identified Bijli bot actors generated into MovementLab for one-,
  four- and seven-bot stress coverage (the scene contains the full seven-bot setup).
- No Aandhi, loot, gadgets, match resolution, Pehel/Maya, networking, backend or final
  art was added.

## Performance observations

- Decision updates are interval-scheduled; after fixing a stuck-state hot loop, the
  stress run measured 91 decisions across two seconds and a 0.024 ms maximum decision
  duration in the headless editor.
- M4 development artifacts are approximately 83.2 MB APK and 113.2 MB Web output.
- No Lava/Oppo CPU/GPU/GC capture, browser frame-time/memory capture or low-end-device
  seven-bot profile was collected. The stress result is not a mobile performance claim.

## Warnings, failures and limitations

- Existing Unity batch logs include licensing-handshake noise and obsolete API warnings;
  builds/tests completed successfully.
- The lab uses bounded CharacterController movement and recovery rather than authored
  NavMesh/pathfinding. Dynamic actor registration is not implemented.
- Debug overlay is an optional immediate-mode presentation aid, not production UI.
- The M4 application ID `com.example.battleraja.m4` is provisional and not a store
  identity. No signing, hosting, Photon, PlayFab, analytics or paid service was added.
